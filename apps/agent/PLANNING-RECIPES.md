# Private planning-recipes-v1

This is an Agent-only model-output IR, not a wire protocol or a new authority. The DSH planner now requests this compact format; legal legacy criteria/cases/coverage still use the unchanged strict `mapModelPlan`. Existing invalid legacy DSL is never normalized or repaired by this compiler. Completed records are not recompiled.

The model declares derived `criteria` with ref/description/sourceSeedRefs and one verification object. It cannot choose required, budgets, paths, tools, IDs or policy. An automated verification lists recipes; manual/unsupported has a concrete reason and no recipes. Every original Seed maps through the existing compiler; host inherits required, retains verbatim parents, and enforces current shared criterion/case/step limits. Manual coverage does not permit omitting the required implementation.

| Recipe | Deterministic host expansion |
|---|---|
| initial_controls | open app; assert initial controls visible |
| text_outcome | open; bounded actions; exact/contains text or value assertion |
| collection_delta | open; save cardinality; actions; nonzero cardinality delta |
| geometry_delta | open; save box; actions; nonzero expected displacement |

Locators are mutually exclusive `{role,name}`, `{label}`, or `{testId}` with optional bounded nth. Host emits actual by/exact fields; it never translates a malformed legacy by:'button'. Bounded actions are click/fill/check/press/drag/reload. No free DSL statements, JS, URL, CSS selector, sleep, arbitrary option or host path is accepted. Each recipe has a fresh browser context. Collection meaning must be structural (listitem/article/option) or supported by hash-verified source, never HUD text. Arbitrary goal-to-test semantic truth remains outside this finite policy.

Geometry requires hypot(dx,dy)>2*tolerancePx and nonzero displacement. The private semantic policy bounded-observation-v3 also rejects empty movement assertions in legacy proposed plans; shared DSL parsing/history is unchanged. Unknown terminal triggers or uncertain spatial assertions remain explicit required manual/unsupported. This is a verification limit, not permission to omit a real 3D world, coordinates, controls or AI behavior.

Successful recipe expansion passes the unchanged mapper, canonical parent projection and full compiled-plan semantic review before freeze. `plan-semantic-review.json` binds the actual final plan hash. Owner600 `recipe-compilation_0|1.json` binds format/compiler version, exact validated IR hash, expanded proposal hash, compiled Spec/Plan hashes and semantic status. Allowlisted bounded proposal JSON is stored separately; no native reasoning, keys or unknown analysis is retained. Compilation does not add a model call, retry or budget. Errors share the original single structural retry with original remaining budget; unsafe/unknown usage remains fail-closed.

Local evidence is synthetic, not DeepSeek generation quality: planning-recipes.test.ts compiles all four general recipes; a real local Chromium runs initial controls, actual text effect, list cardinality and key-driven 40px movement. Removing movement fails that same assertion. Negative tests preserve the captured by:'button' failure shape, empty displacement, unknown terminal recipe, unproved HUD collection, authority/locator ambiguity, absent source mapping and limits. A native-free mock DSH goes malformed IR → one corrected IR → bound final receipt; no Provider or Docker is used. Existing legacy capture, cumulative usage, fresh Worker context and required/manual tests remain in the targeted suite.

A further real 3D quality result requires the manager's separately bounded model validation. These compiler/browser tests do not claim that a model has generated playable 3D or that manual criteria passed.
