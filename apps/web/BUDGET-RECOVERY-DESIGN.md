# 预算中止与换额继续：Web 消费设计（待后端 G0）

日期：2026-11-09；工作树基线 `811f3ac`。已读 AGENTS、架构、公共接口与并行计划。本文件仅描述 UI 和协议消费要求，不定义路由/DTO/枚举、不改旧 wire、不实现服务或 UI。后端是新增 budget-recovery 共享 G0 唯一作者；主管冻结并同步后再实施。无真实模型调用，不运行用户生成源码，不改现有3D任务/报告或历史结论。

## 1. 展示位置与语义

在既有任务失败卡片的原 error 下增加预算诊断/恢复区，不用通用“失败重试”替代。旧 Run 始终保持原 failed 状态，原报告、尝试、错误、质量缺口和上一成功预览不变。后续任务成功也不能把旧记录改成成功。

仅在 API 返回预算诊断时展示具体预算维度、限额、计量时间与来源。输入/输出 Token、模型步数、时间与修复轮数分别说明；其他失败（模型格式、验证、依赖、网络、取消等）不能伪装成“加 Token 即可修复”。没有权威诊断的老任务保留原通用失败原因，明确未记录细分用量，不编造0、估算或可恢复承诺。旧3D任务不一律作为legacy拒绝：若API/Agent新增结构化只读审计能证明真实输入超限、停止和可恢复源码事实，则可依据该新权威诊断显示恢复卡；Web不能从错误文字推断，也不回写历史Run/报告。

已观察用量下界与最终已结算值分开：例如“已观察输入至少 X（含缓存计量）；最终结算尚未知”。只有 API 明确 settled 时展示最终值。不能由预算阈值推算实际用量、把流式下界当最终账单或生成虚假完成百分比。旧3D结果只展示已存事实，不为文案重跑或改写。

## 2. 用户操作

读取 API 权威恢复视图后显示当前可恢复状态/具体阻止原因、剩余可用构建次数和固定后续预算。仅当 API 明确 eligible，且有可信可恢复源码、旧执行终止已确认、有额度、目标绑定仍有效时启用。

操作前直接可见：

> 本操作将预占1次构建额度，后续任务实际开始时结算，为其追加输入65,536 / 输出24,576 Token预算。从已保存源码继续，不从头生成。新段仍最多8个模型步骤、15分钟、2轮修复；追加预算不保证一定完成。

唯一主按钮：“消耗1次构建额度，追加预算并继续”。沿用14px正文/按钮和12px元信息，小屏可换行，不靠缩字容纳。新增额度是应用执行预算，不宣传成provider充值或绝对费用硬上限。按钮前的清晰说明即确认，不再叠加无必要审批步骤。

点击后立即禁用、显示“正在确认后续任务”；请求具有稳定幂等键，不走普通createRun或自然语言消息提交。已受理时显示后续任务链接与API返回的当前余量；排队只称预占，实际started后才称结算，未开始取消/释放以API为准，不提前称永久已扣。用户可定位后续任务并查看从哪个保存点继续。后续执行、发布与M2验证仍独立成立，不能跳过原required检查。

恢复卡同时说明沿哪份冻结目标/验收计划继续：“追加预算不会自动修正原验收语义，也不保证生成或修复质量”。如果底层判定计划语义无效，显示API的准确原因/限制，不暗示换额即可让错误计划合理。该说明与后续多轮完整目标汇总相容，不在本卡编辑required或冻结断言。

## 3. 提交、刷新与并发

- 提交前保存仅含旧Run/恢复提议绑定与幂等键的本机会话记录，不保存源码、模型凭证或用户体验码。是否需要恢复操作ID及查询路径由后端G0定义，不在Web自造。
- 网络丢回应显示“提交结果尚未确认”，按钮不能回到可创建新任务状态。先查询 API 权威恢复/已有successor状态；需要重试时沿用同一键，不生成新键盲重造。刷新后同样先对账。
- API返回已存在后续任务时直接定位，不重复扣次数；跨页/浏览器和不同键的唯一性必须由服务端约束，前端disable不足以证明。
- 409或恢复源/版本/offer revision变化时重读，显示差异并让用户重新点击；不把旧授权自动换成新源码或新预算。
- 配额不足、会话失效、限流、服务不可达分别显示；登录恢复不自动提交或创建后续任务。已扣/预占/释放以API快照为准，不在前端自行减1再宣称结算。
- 切项目/Run或关闭面板使旧响应失效；generation+subject绑定，不能让A的后续任务回执覆盖B。
- 旧失败卡片保留“已创建后续任务”，后续任务展示来源Run/root lineage。跳转只读定位，不再次执行。后续再预算中止时是否允许再换额，由它自己的API eligibility/配额决定，不提供无限自动续费循环。

## 4. 后端契约消费要求（字段命名/路由待G0）

| 必需语义 | Web用途与禁止推断 |
| --- | --- |
| 诊断绑定旧project/Run、触发预算维度与limit、发生/计量时间 | 不能通过error字符串猜类型，不能串到另一任务 |
| observed lowerbound与settled最终值分开、输入含cache、settled未知可空 | 不将未知写0，不把下界当最终账单 |
| eligibility与不可恢复原因（含非Token/无源/未停止/额度/冲突/legacy） | 仅API授权启用按钮，不靠BUDGET_EXCEEDED枚举自行启用 |
| 恢复源码checkpoint的可信引用/指纹、终止fence事实、offer/policy/revision绑定 | API/Agent核验实际源码，Web不获取宿主路径、不执行用户源码 |
| 固定消耗1次构建及输入65536/输出24576、8步/15分钟/repair2 | 动作前展示准确成本/新段边界，不允许Web传任意放大预算 |
| 当前quota/预占/used及时间 | 等待、刷新、成功/冲突后都能显示权威余量 |
| 提交稳定idem和预期revision；已接受/结果未知/已有successor的可查询事实 | 丢回应和刷新不重复创建/扣额，跨浏览器由API保证唯一 |
| successor Run和parent/root lineage、准确恢复源 | 明确后续任务而非原Run复活；不静默选最新已发布版本重新生成 |
| 安全错误与scope归属 | 旧任务无权限统一拒绝，错误不泄露内部路径/凭证 |

恢复应使用已保存的可信源码继续，而非旧已发布基线重跑。若没有可恢复源码或旧执行仍可能写入，API必须不给eligible；Web不承诺“继续”，也没有绕过按钮。旧报告、冻结目标/计划的保留或合法后续绑定方式由后端/Agent G0明确，不能以增加预算修改required/断言洗掉既有失败。

## 5. G0后的独立验证矩阵

| 场景 | 独立Mock/单测/浏览器必须观察 |
| --- | --- |
| 输入或输出Token中止且eligible | 预算类型/限额、明确1次成本、固定新预算、保存源码继续说明；按钮可用 |
| observed已到阈值但最终settled未知 | “至少/未知”区分，不显示伪造最终结算 |
| 时间/步数/修复预算或其他失败 | 真实原因；没有“加Token必修好”按钮 |
| 保存源码缺失/损坏、终止未确认、过期或基线冲突 | API reason可见；不可自行降级为从头重试 |
| 老Run无预算诊断与当前3D旧报告 | 原error/质量/报告如实保留，不造历史数字或新执行 |
| 点击双击、响应丢失、刷新后查询、重试 | 立即禁用，稳定同key，已有successor只定位，最多一次新Run与扣额 |
| quota不足/401/429/503/409 | 分别反馈，重登录/重读不自动提交，不自行改权威余量 |
| 切项目/Run后迟到响应 | 不串subject、不改错任务余量或跳转 |
| 后续任务排队/完成/再失败 | 原failed/报告保留，lineage正确，新段上限明确；旧预览仍按发布事实展示 |
| 1440/390布局 | 14/12尺度、清晰成本、完整按钮、键盘可达，不整体缩放 |

使用后端冻结共享fixtures，通过真实HTTP Mock模拟；不导入API/Agent实现、不调用provider、不执行用户生成代码。前后比对消息不新增、恢复只走专用受权入口；新的后续Run是这项操作明确授权的唯一业务变化，不能把它描述成只读动作。
