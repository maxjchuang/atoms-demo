# 预算中断提示与一次构建额度续作

日期：2026-11-09。用户要求：预算中止明确告知原因，并允许显式消耗一次构建额度换取 Token 继续。本轮仅本机初步验收，暂停 Cloudflare / Intel 迁移工作；主管管理协议、审查、测试、Git 与安全升级，三条实现线分别执行。

## 行为与授权基线

- 不自动追加预算，不把预算失败包装成通用网络错误。展示实际触发维度、限额、已观测值及是否完整结算；未知用量保持未知，不显示为零。
- API 独占体验身份、额度、项目锁和发布。一次明确操作最多授权一个后续 Run，预占1次构建额度，真正开始执行后按既有规则结算；重复点击、丢回应、并发与重启不得重复授权/扣额。
- 原失败 Run、不可变报告、源码快照、已用额度和未知计量保留。后续 Run 可追踪 predecessor/lineage，从受控的最近验证源码继续，不重走 Router/规划，也不复活旧任务。
- 同一目标、验收语义、步骤、required 与发布规则保留。若新 Run 需新主体标识，明确重绑定与来源，不伪称新旧 hash 相同。计划本身的语义错误须另行修正，不靠续费绕过。
- 每次新增有界执行段：输入65536、输出24576 Token，最多8个可观察模型步骤、900000ms active 与2次修复；这是新的授权段，不抹去前段支出或承诺一定成功。
- 仅 Token 预算失败且源码/计划完整、旧执行已确认停止、没有新版本或其他任务使基线过时等条件均成立时提供续作。其他预算/未知或源码不可恢复时给出具体原因，不暗示加 Token 能解决。
- 同一失败 Run 最多一个 successor；后续若再次失败，只能在其自身满足条件时重新显式授权，并受剩余额度限制。取消、幂等、跨用户、过期、额度预占、排队和发布 fence 沿用权威边界。

## 分工与门禁

1. 后端线独占新增独立 budget-recovery shared module、fixtures/tests、package exports 与协议 Markdown；先与 Agent 对齐内部诊断和受控恢复快照接口。旧 strict execution/conversation/delivery DTO 不直接扩大。主管审查 G0 后三消费者才实现。
2. Agent 线拥有 budget cause 的结构化记录、观测/完整结算区分、停止确认、源码快照/hash验证、从快照执行的新段与独立计量；不管理业务额度。
3. API 线拥有 descriptor/quote/显式提交、权限与原子额度预占、唯一 successor/新 Run/内部 outbox、重启对账及 lineage；不读取模型 Key/隐藏 native 历史。
4. Web 线展示明确预算卡片、固定追加成本/预算与失败风险、剩余额度和续作结果；幂等提交、断网未知态、刷新/晚到响应、不可用原因及旧报告仍可访问。
5. 各线用 Fake、Schema、HTTP 与 Mock 浏览器独立测试，不自动重跑用户3D任务或调用模型。主管再独立复验 API/Agent 全链路、取消/重启/重复点击/未知计量及兼容，审查后集成。
6. 更新本机5180验收服务前排空全部非终态（含准备完待冻结）、确认停止并完整备份。旧项目、历史、额度和失败证据不重置；确认新版登录/预算提示可读，续作只由用户点击授权。
