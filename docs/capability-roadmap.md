## 3. M1：项目协调

### 范围

- 项目级持久 Router，或通过验收的可靠持久项目上下文恢复；不能仅上一版 summary。
- 新项目消息入口，独立 CoordinationTurn、结果、提案和澄清生命周期。
- 默认 auto；明确修改直接准入排队，咨询只答；ask 硬只读，build 也不强迫咨询转写。
- latest 意图队列与 exact 版本提案明确区分；API 仍唯一授权建 Run。
- 显式短答绑定、历史分页、双事件游标、旧数据兼容迁移；消息准入成 Run 不重复显示原用户消息。
- 实际兑现已有 Run-level question Attention：options/text、revision、重启恢复与原 answers，不仅是 plan_confirmation。
- 独立有界 Router/Worker 计算槽，独立消息次数、token 和限流；受限取消控制。

### 门禁

1. 文档与共享契约冻结，三方向据同一 v2 协调契约独立测试；旧 v1 执行测试继续通过。
2. 代表性咨询/状态/修改/模糊/短答/取消场景，无错误 Run、错误目标或重复扣额。
3. 项目偏好与决定跨消息、跨 API/Agent 重启仍可恢复；Worker 长任务期间可咨询。
4. 旧项目、对话、版本和活动全部可读，不自动重跑历史，无数据/额度重置。
5. 有界真实 Router 样例验证，分别记录模型调用次数与只读/写入结果；不以关键词替代语义协调。

## 4. M2：可信交付

### 范围

- 版本 diff：added/modified/deleted 路径和安全文本差异，默认与父版本比较；不在工作台执行生成 HTML。
- 源码导出附生成应用 lockfile、固定运行要求与说明，使用新目录实际安装/构建复验，不依赖平台 node_modules。
- 验收项到受控浏览器操作/断言的映射，区分 required、可选、未支持和未运行；不允许模型随意评估为通过。
- 保留真实失败证据、修复预算和版本发布 fence，输出诚实的完整/部分交付状态。
- 补完整 G4：真实模型在恢复后的新版本继续修改，确认基线、父版本、预览与声明行为。

### 门禁

1. 两版源码 diff 与实际文件变化一致；恢复版再修改仍可追踪完整父子历史。
2. source.zip 在干净目录通过 frozen-lockfile 安装与 build，导出不含凭证/DSH home/内部日志。
3. 至少一个真实代表应用具有自动声明行为验收与失败→修复→复验的真实证据；不伪造原始历史。
4. 完整 G4 真实样例通过，明确费用、预算、失败和未覆盖项。

当前门禁记录：1、2 及真实恢复后修改/重启/只读 UI 已有受控样例证据；第 3 项由独立受控故障的真实 DSH 修复和同计划/clean ZIP 动态复验补齐；明确不是自然生成缺陷。exact 提案的显式接受满足授权边界，原 runner 的 auto 断言失败不能改写为成功。M2 生产包与工具分项计数见 [M2 状态](m2-delivery-status.md)。

## 5. M3：隔离公网

### 范围

- 每任务隔离执行，明确文件挂载、进程、网络、资源、时限、凭证边界；禁止暴露 Docker socket 或宿主 home。
- Docker Compose 部署与持久化卷，验证 Linux 行为及停止/重启后旧执行不能继续发布。
- 工作台与预览两个 Cloudflare 隧道，配置受信 Origin/Host、签名资源路径、Cookie 和预览静态路由。
- 体验码、限流、总预算、故障恢复和临时域名生命周期说明。
- 真实分享验收：另一浏览器/设备从外部打开并交互，确认可用范围、有效期与权限；咨询答案引用实际部署状态。

### 门禁

1. 生成进程/浏览器无法读取模型 Key、服务令牌、其他项目或宿主文件；外连与资源限制符合策略。
2. 取消、崩溃和重启后无旧进程继续改写/发布；持久化卷可恢复。
3. 工作台和预览域分离、API 不能从预览源调用、内部端点无公网暴露；脚本/资源加载与存储实际通过。
4. 外部可测试链接与分享路径通过，原用户数据不公开越权，临时链接失效条件写清。
5. G5 完整验收后才标为可公开体验；本机成功不替代隔离和公网证据。
