# 能力差距与交付路线图（G0 已冻结）

日期：2026-11-08。用户已选择按 **项目协调 → 可信交付 → 隔离公网** 补齐。G0 文档与 Schema 已经主代理审查冻结，contracts check 与 40/40 测试通过，原 v1 index/fixture/tests 无修改；M1 服务实现待开始。本文是差距台账与后续门禁，不是新功能已完成声明。

现有生成链路和测试记录保留在 [实施记录](implementation-status.md)；M1 新协议见 [v0.2 项目消息协调协议（G0 已冻结）](protocol-v0.2.md)。

## 1. 基线与当前状态对照

| 原设计/要求 | 当前已验证范围 | 差距分类 | 后续归属 |
| --- | --- | --- | --- |
| 项目级 Router + 任务 Worker，持续负责项目 | 每 Run 独立 Planner/Worker；跨 Run 仅已发布源码+上一版摘要 | 设计能力缩减，非完整项目协调 | M1 |
| 消息咨询/状态/修改目标的自然交互 | v1 只有 GET messages、POST runs；输入均建任务 | 新消息协议未定义；不能说原 v1 已有只读问答 | M1 |
| 普通问题 Attention、必要澄清 | 后端 Schema/fixture 支持问题，运行时主要实现计划确认 | 实现覆盖不足 | M1 同时补普通 Run question Attention 与消息级澄清；原 Run 计划确认保留 |
| 低打扰执行与过程可见 | 三层进度反馈、真实时间线、断连/恢复已测试 | 本轮过程反馈已交付，仍非完整 Router | 已有证据保留，M1 接入协调状态 |
| 持久化、队列、配额、发布边界 | API 单进程 SQLite、项目锁、独立 Runtime 账本、原子发布已验证 | 已实现；单进程 JSON 快照是披露取舍 | M1 增补协调存储，不能重置已有额度/历史 |
| 版本差异与回滚 | 文件只读查看、版本列表、不可变恢复；没有完整 diff 能力 | 计划能力尚未补齐 | M2 |
| 可导出、可复现的 React 项目 | 导出真实源码和精确直接依赖；构建用预装可信依赖，生成应用 lockfile 尚缺 | 交付可复现性不足 | M2 |
| 验收约定驱动验证修复 | typecheck/build/smoke 自动执行；一般 behavior=not_run；真实样例另有只读行为验收 | 通用/声明行为覆盖不完整，不得把 smoke 当全部行为 | M2 |
| G4：真实生成、修改、验证、回滚后修改 | 两次真实生成/修改、发布、恢复、重启通过；回滚后再次修改仅 Fake 覆盖 | 原 G4 门禁未全部闭合；已有“通过”应限定最小子集 | M2 |
| 受控执行与最小权限 | 模型工具禁用、受控源码应用、子进程环境清理；无每任务 OS 容器隔离 | 原隔离门禁未完成，不能公开执行不可信任务 | M3，公网前硬门禁 |
| 本机 Docker + 双 Cloudflare 隧道 + 在线链接 | 当前仅本机服务 | G5 未完成，尚无可交付公网生成链接 | M3 |
| 分享给别人 | 本机预览、源码下载；无真实公网分享流程 | 产品能力缺项，不应靠修改应用替代部署 | M3；M1 必须据实回答 |

## 2. G4 口径纠正与历史证据

[原并行计划](parallel-plan.md) G4 包含“回滚后修改”。现有真实模型集成没有执行恢复后的第三次模型修改，因此不能将完整 G4 基线全部标记通过。

准确表述：**G4 的真实模型最小子集通过，完整 G4 尚差真实回滚后继续修改及对应验收**。此前成功的两次真实调用、manifest、截图、版本关系和重启恢复仍有效，不删除、不改写，不用 Fake 结果顶替。

真实样例的追加只读浏览器检查覆盖新增、编辑、搜索与刷新保存，modelCalls=0、未改生成文件。原自动 manifest 的 behavior=not_run 仍保持原值；追加证据不能扩大成任意应用行为已通过。

## 3. M1：项目协调

### 范围

- 项目级持久 Router，或通过验收的可靠持久项目上下文恢复；不能仅上一版 summary。
- 新项目消息入口，独立 CoordinationTurn、结果、提案和澄清生命周期。
- 默认 auto；明确修改直接准入排队，咨询只答；ask 硬只读，build 也不强迫咨询转写。
- latest 意图队列与 exact 版本提案明确区分；API 仍唯一授权建 Run。
- 显式短答绑定、历史分页、双事件游标、旧数据兼容迁移；消息准入成 Run 不重复显示原用户消息。
- 实际兑现已有 Run-level question Attention：options/text、revision、重启恢复与原 answers，不仅是 plan_confirmation。
- 独立有界 Router/Worker 计算槽，独立消息次数、token 和限流；受限取消控制。

### 门禁

1. 文档与共享契约冻结，三方向据同一 v2 协调契约独立测试；旧 v1 执行测试继续通过。
2. 代表性咨询/状态/修改/模糊/短答/取消场景，无错误 Run、错误目标或重复扣额。
3. 项目偏好与决定跨消息、跨 API/Agent 重启仍可恢复；Worker 长任务期间可咨询。
4. 旧项目、对话、版本和活动全部可读，不自动重跑历史，无数据/额度重置。
5. 有界真实 Router 样例验证，分别记录模型调用次数与只读/写入结果；不以关键词替代语义协调。

## 4. M2：可信交付

### 范围

- 版本 diff：added/modified/deleted 路径和安全文本差异，默认与父版本比较；不在工作台执行生成 HTML。
- 源码导出附生成应用 lockfile、固定运行要求与说明，使用新目录实际安装/构建复验，不依赖平台 node_modules。
- 验收项到受控浏览器操作/断言的映射，区分 required、可选、未支持和未运行；不允许模型随意评估为通过。
- 保留真实失败证据、修复预算和版本发布 fence，输出诚实的完整/部分交付状态。
- 补完整 G4：真实模型在恢复后的新版本继续修改，确认基线、父版本、预览与声明行为。

### 门禁

1. 两版源码 diff 与实际文件变化一致；恢复版再修改仍可追踪完整父子历史。
2. source.zip 在干净目录通过 frozen-lockfile 安装与 build，导出不含凭证/DSH home/内部日志。
3. 至少一个真实代表应用具有自动声明行为验收与失败→修复→复验的真实证据；不伪造原始历史。
4. 完整 G4 真实样例通过，明确费用、预算、失败和未覆盖项。

## 5. M3：隔离公网

### 范围

- 每任务隔离执行，明确文件挂载、进程、网络、资源、时限、凭证边界；禁止暴露 Docker socket 或宿主 home。
- Docker Compose 部署与持久化卷，验证 Linux 行为及停止/重启后旧执行不能继续发布。
- 工作台与预览两个 Cloudflare 隧道，配置受信 Origin/Host、签名资源路径、Cookie 和预览静态路由。
- 体验码、限流、总预算、故障恢复和临时域名生命周期说明。
- 真实分享验收：另一浏览器/设备从外部打开并交互，确认可用范围、有效期与权限；咨询答案引用实际部署状态。

### 门禁

1. 生成进程/浏览器无法读取模型 Key、服务令牌、其他项目或宿主文件；外连与资源限制符合策略。
2. 取消、崩溃和重启后无旧进程继续改写/发布；持久化卷可恢复。
3. 工作台和预览域分离、API 不能从预览源调用、内部端点无公网暴露；脚本/资源加载与存储实际通过。
4. 外部可测试链接与分享路径通过，原用户数据不公开越权，临时链接失效条件写清。
5. G5 完整验收后才标为可公开体验；本机成功不替代隔离和公网证据。

## 6. 范围和评审纪律

M1 优先，不同时启动 M2/M3 大规模实现；但 M2/M3 保持可见台账，不能因先做 Router 就遗忘真实笔试在线交付要求。

每阶段先文档/契约，再独立替身验证、真实服务联调和必要有界模型样例。新能力应称新增范围或补齐原设计差距，不一概叫 v1 bug；不破坏已经稳定的生成队列、授权与交付链路。
