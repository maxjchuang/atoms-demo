# 协调上下文压缩与缓存前缀优化（最小交付）

## 范围

仅调整 Agent 协调器的模型输入视图：固定指令、原协议形状与需求规则前置；动态时间、修订/hash、部署信息及当前输入后置；去重交付报告和已存在的用户正文。API 权威数据、完整需求账本、确认与执行授权逻辑保持原样。

模型侧交付事实保留 Run/Version 主体、质量、报告引用、缺口计数，以及当前版本、活动任务、最近失败任务的缺口状态；长描述按预算保留，明确标注省略，不能将省略视作通过。原始报告及 hash 保留在宿主。当前输入通过引用避免重复，绑定的澄清问题及用户回答保留。普通用户和模型正文不得按长度截断。

## 预算与边界

不启用 UTF-8 字节估算硬拦截。字节数只作上下文大小观测，不是精确 token 数。现有模型实际用量计量和累计输入上限继续生效；缓存命中的输入也计入预算。没有新增付费压缩模型、插件或 SDK 升级。

原始失败请求的只读离线投影：deliveryFacts 104,466 字节降至 5,457 字节；两个完整提示词约 2.3 万字节。此结果是输入体积对比，不代表真实 token 数、模型成功率或缓存命中率。后续实际对话可用模型 usage 和 model-input-projections.jsonl 元信息验证；元信息不写入正文或密钥。

## 验收

在合并候选上运行 Agent 类型检查及相关测试，覆盖原规则保留、权威输入不变、澄清绑定、来源/当前输入去重与读取/重试可执行。无需调用 DeepSeek 或消耗用户构建额度。

## 限制

压缩视图不包含全部历史报告长描述或失败原因，详细诊断仍需查看宿主原报告；本次没有新增模型读取报告工具。稳定前缀只改善可复用条件，项目状态变化仍会改变快照；不保证缓存命中率。既有累计输入预算仍可能因完整需求或多次读取耗尽，本次不宣称解决所有超预算场景。
