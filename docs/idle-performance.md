# API 等待状态的资源消耗修复

## 问题与范围

2026-11-10 在部署机观察到：没有执行中的模型请求或隔离任务，两个 Run 均等待输入，但 API 仍按默认500毫秒周期检查 Agent 健康及隔离能力，并同步未变化的交付报告。6秒内捕获15次 broker 子进程 `docker image inspect`；同一报告 revision/hash 和截图内容不变，截图修改时间与 SQLite WAL 却持续更新。基线资源记录保存在部署机私有目录 `~/.local/state/atoms-demo/idle-perf-20261110/`。

本次只修改 API 调度、交付同步及对应测试。不改变协议、模型预算、冻结 Seed/Spec/Plan、验收 required、质量政策、隔离认证元组或已发布版本，不处理清单/CSV 测试规划错误。Agent、broker、任务镜像和网关实现保持原样。

## 行为变化

- 定时器仍每500毫秒进行轻量检查；已确认执行且等待输入的任务默认每5秒向 Agent 同步。回答、取消、未确认投递及新派发工作不受该等待间隔限制。
- 只有确需派发时执行健康和隔离就绪查询；公开准入和首次 Preparation/Execution 派发前仍实时核对隔离绑定，不以历史认证缓存放行。
- 请求已获得并持久化受理确认后，不再反复 PUT；结果不明确的请求继续使用原不可变身份核对与重试，不创建新执行或重复扣额。
- 报告的身份、冻结绑定、版本、哈希、历史证据和已封存对象仍校验。仅对完全相同且已完整导入的报告复用本地文件；复用时重新读取报告与证据并核对内容。缺失或损坏时失败关闭，不静默补写或忽略。
- 同一报告不再重复下载、写入证据和保存报告。用量、停止状态及投递标记没有变化时不提交业务事务。

等待状态下，从 Agent 外部发生的变化可能最多延迟约5秒被同步；用户提交的回答和取消仍由下一轮轻量调度处理。任务等待不表示终态，不释放项目锁。

## 验证

在独立工作区执行 API 类型检查、API测试140项、契约类型检查与契约测试125项，均通过。独立审查另覆盖交付、修复控制、预算恢复及新增性能场景。历史 public legacy 执行重试也检查实时隔离就绪；取消路径不通过 PUT 重建执行，且不依赖就绪证明才能继续停止核对。

新增测试检查真实定时器间隔、隔离状态变化后重新拒绝派发、无变化时的 PUT/证据请求/数据库变更/文件修改时间、报告变化与损坏、连接恢复、回答和到期处理。公开测试实例执行 API 关闭/重开，核对 writer lease、业务状态、项目锁、待回答问题、额度及版本保持，未使用真实模型或公网项目。

生产 CPU 降幅须以上线后的同负载动态采样为准；单元测试通过不代表实际资源降幅已达标。虚拟机缓存内存不承诺立即下降。

## 同协议 API 单服务维护

仅适用于本次不改变协议、冻结计划及 Agent/任务配置的 API 更新。`protocol-delivery-v0.1.md`第14节的 canonical projection 升级门禁仍适用于其对应语义升级，本次不重编译旧 proposal 或给旧报告套用新投影。

现有统一 `./atoms restart` 会等待所有任务排空；存在等待输入任务时，不用它强制推进本次更新，也不自动取消或回答任务。维护流程为：

1. 先完成独立测试、候选镜像检查及容器 SIGTERM 优雅退出验证，记录旧 API 镜像与回滚资料。
2. 短暂暂停公开写入准入，核对只有预期等待任务，无模型请求、未确认隔离任务、待投递回答或活动协调会话；保存任务、额度、锁、部署绑定和隧道身份摘要。
3. 仅停止 API，给予足够退出时间。确认实际容器退出、writer lease 正常释放，再做停止写入后的完整数据卷备份；不在运行中的 SQLite 上做不一致文件拷贝。
4. 使用同一 Compose project、工作目录、数据卷、配置及服务凭据，只更新 API（`--no-deps`）。既有 `recover('start')`仅在已证明 API 停止后支持同身份恢复；禁止直接删未知 writer lease。
5. 新 API 就绪后核对任务身份、待回答问题、项目锁、版本、额度和隔离元组未变，再恢复准入。失败则按原镜像恢复；不把 HTTP 超时解释为任务已经停止。
6. 验证公网入口并观察5至10分钟，比较资源占用、报告/证据修改时间、数据库写入和镜像检查频率。保存脱敏证据。

整个流程不停止共享 Docker VM，不重启 Agent、broker、网关或隧道，不轮换域名、签名或模型凭据。后台本机监控可能记录维护期间的暂停/短暂不可用；这些事件按实际保留。
