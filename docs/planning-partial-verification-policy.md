# 单条自动验收失败的最小部分交付策略

本轮仅使用既有manual/unsupported coverage与partial质量状态，不扩充Space等DSL能力，不增加模型重试次数或预算。

模型规划首先接受逐条、汇总的精确诊断，在原一次结构纠错后仍无法建立可靠自动验证时，只允许将该criterion的verification显式改为manual并保留具体原因。完整产品description、required、Seed来源和引用映射保持；原始模型计划、诊断及降级回执保留。其余有效自动条目正常编译、运行。未执行的自动脚本不能视作通过。

核心criterion结构、产品/Seed覆盖、来源与权限不合法不得通过manual兜底；畸形JSON不允许猜出产品要求。类型检查、构建、基本加载与仍声明为自动验证的必需用例失败，继续阻止发布。

工程硬门槛通过且有人工缺口时，按既有partial规则提供带缺口预览，明确显示哪些自动通过、哪些仍需人工验收及原因。全部人工覆盖仍仅有基础运行证据，不能称为完整功能验证通过。人工覆盖不授权省略功能实现。

开发总墙钟上限15分钟，到期即停止报告。此轮不调用真实模型或重放用户构建；使用共享协议、模拟规划/HTTP和浏览器回归，不扣用户构建额度。
