# Budget recovery 0.1.0 — G0 candidate

This is a candidate contract, not implemented service behavior. It adds `@atoms/contracts/budget-recovery` and fixtures only; execution 0.1, conversation 0.2 and delivery 0.1 DTOs, status enums and historical data are unchanged. The API owns admission, identity, quota and publication. Agent owns diagnosis, source preservation/copy, resource-stop proof and Worker verification. Web only displays API facts and requests one explicit authorization. There are no model calls in G0.

## Authority and user action

A failed Run is never revived. An explicit “consume one build credit and continue with another bounded token segment” action creates one linked successor Run, preserving the failed Run, final report, all attempts, history and unknown usage. The predecessor may have at most one successor for its lifetime, across sessions/browsers/keys/restarts. The identity/code and project own that relationship; the existing session-scoped mutation cache alone is insufficient. A later token-budget-failed successor may receive its own explicit authorization only while it is the chain's latest failed Run and the current project target/head are still compatible. No automatic further task, Router call, planning call, goal correction, quota reset or extra credit exists.

Each successor reserves one build credit under the ordinary effective quota (including any independently authorized public handoff). The existing first-billable Worker `execution.started` authority converts that reservation to used once. Copy/verification/HTTP acceptance alone do not fabricate model usage. Definite pre-start failure releases its reservation under existing semantics, but the predecessor→successor relationship remains consumed: failure cannot create unlimited replacements. Each new segment is fixed at 65,536 effective input tokens (including cached input), 24,576 output, eight observable model steps, 900,000 active milliseconds and two repairs; other fixed fields are defined in `RECOVERY_SEGMENT_BUDGET`. Historical unknown input/output stays null, not zero. Segment spending is not presented as a known chain total when an older segment is unknown.

Only an actually diagnosed **segment token** budget failure can offer continuation. The diagnostic separately records dimension, observed lower bound, nullable settled total, limit and optional next-request reservation. `segment_limit_reached` needs an observed bound at the limit; `request_reservation_rejected` means the known next-request reservation exceeds the remaining segment allowance, not that all those tokens were consumed. Generic `BUDGET_EXCEEDED`, `max-tokens` alone, provider context limits, tool timeout, wall-clock deadline, repair/step limits, or unknown cause do not imply token eligibility. Native private reasoning is never returned. Public text distinguishes historical settled/unknown from observed lower bounds.

Known semantic defects block paid recovery with `PLAN_REVIEW_REQUIRED`; unassessed plans fail closed too. A syntactically valid DSL is not evidence of semantic usability. `planReview.reusable` denotes only the actual limited host plan-review policy, not a proof of arbitrary application semantics; the subsequent quality-policy module defines checks/limitations and its detailed receipt without changing old delivery DTOs. The existing 3D run's known count/terminal-trigger defects cannot be bypassed by another token credit. The user must review a corrected accumulated requirement/plan as a separately authorized new task; old required criteria/tests are never silently rewritten. The detailed requirements/quality evolution is a separate G0.

## Routes and authentication

All new routes require `X-Atoms-Budget-Recovery-Version: 0.1.0`, echoed on successful responses. Existing cookie identity/project authorization and exact Origin rules apply publicly. Internal calls require the existing service Bearer; visitors cannot assert `stopped=true`, choose paths, send model credentials or call internal resource control.

| Public route | Contract / effect |
| --- | --- |
| GET `/api/budget-recovery/v1/runs/:runId` | `BudgetRecoveryReadView`: diagnosis, authoritative eligibility/reason, fixed quote, preserved goal/criteria, predecessor/root/successor relation and current quota. No Run/admission/quota/history/event/model/stop mutation; bounded quote-cache persistence may occur (see below). |
| POST `/api/budget-recovery/v1/runs/:runId/continue` | `ContinueBudgetRequest` + Idempotency-Key → `ContinueBudgetResponse`. One explicit successor authorization. |

| Internal route | Contract / effect |
| --- | --- |
| GET `/internal/budget-recovery/v1/executions/:executionId` | `RecoveryRuntimeView`: immutable origin wrapper/report refs, typed diagnosis/checkpoint, current confirmed-stop receipt and separate plan-review verdict. No inference. |
| POST same path + `/confirm-stop` | `RecoveryStopRequest` with commandId and exact original request/report/checkpoint. Idempotent owned-resource disposal/audit only; no inference or quota. |
| PUT `/internal/budget-recovery/v1/executions/:newExecutionId` | Immutable `RecoveryExecutionRequest`, first 201 / identical retry 200 / different body 409. Does not accept ordinary delivery PUTs as recovery. |

After accepted recovery, existing delivery execution GET/events/cancel/report/artifact paths serve the new execution and ordinary M2 publication evidence; those wire DTOs do not gain variants. A missing immutable recovery outbox is never reconstructed from changed live facts. API persists full request, hash, stop/checkpoint/authorization and lineage before its first PUT. On restart it reconciles the same execution ID/body, never creates another model execution. New Worker start authorization expires after at most five minutes. Agent must fence first model start against it; an already-started execution remains observable/cancellable and is not replayed when the authorization expires. If no start was ever dispatched and authorization expires, fail/release safely. If acceptance is uncertain, reconcile/cancel the same ID and retain its lock until actual stop; never silently dispatch it later or falsely claim stopped.

## Checkpoint and stopping

This baseline supports `host_local` only. Docker recovery is explicitly `BACKEND_UNSUPPORTED`, without host fallback or bypassing isolation. A checkpoint is an Agent-private immutable copy of the **last fully applied source**, not an incomplete streamed response, template regeneration or newest published version. It includes package/lock/config fingerprints, complete source inventory hash, source snapshot hash, file count/bytes, actual origin binding/Seed/Spec/Plan refs and toolchain. Agent hashes actual bytes when sealing, before copying, and after copying; changed/missing/unrecoverable files reject. No home path, SDK/native directory, token, dependency store, dist, credential or arbitrary host path enters the source copy. API never writes Agent directories; it verifies authenticated descriptor seals/origin refs, and the recovery endpoint independently checks its own sealed source bytes. Published artifacts later pass all normal independent API bytes/hash/plan/attempt/export gates again.

An old failed status, empty in-memory slot, or `pendingModelRequest` flag is not stop proof. Runtime disposal must confirm all owned SDK/Worker resources quiescent before persisting a stop receipt. A historical host run may use a separate zero-model audit of current UID, fixed verifiable SDK/native executable, exact patch ownership, process tree/argv/CWD; it must not read process environments or private reasoning. Incomplete enumeration, ambiguous ownership or relevant residue is `STOP_UNCONFIRMED`. It must not kill another project. The receipt binds private control epoch, audit time, original request/report/checkpoint hash. API must hold an idle project writer context, reject any nonterminal work/existing successor, and obtain current matching proof **before** reserving a credit/creating a successor. Public GET never performs resource control, admission, quota/history/event writes or inference. It may materialize/refresh only a bounded quote/diagnostic read cache; this is not a claim of zero storage writes. A private reconciliation/cleanup outbox may obtain the zero-model stop proof before eligibility is offered. Service unavailability means no eligible quote/admission, not blindly consuming credit.

## Same semantics, honest rebinding

`recoverySemanticBody` freezes the full goal, all original Seed items/source evidence, criterion descriptions/required/mappings, cases/steps/coverage/DSL/browser budget, base context, original real preparation ID, toolchain and delivery/export policies. Consumers SHA256 its canonical JSON. No criterion, ID mapping, source requirement or test may disappear or become optional. Nested item/criterion/case/step IDs stay unchanged. `rebindRecoveryRequest` only reseals top-level Seed/Spec/Plan/binding IDs, new run/execution refs, revision/timestamps and their DAG hashes. Its execution preserves **every** original field except run/execution IDs and the fixed new budget, including prompt, mode, mandate, project, attempt and input.

The new bundle explicitly reuses the real origin `preparationId` as provenance, with `planningMode` preserved and **new-segment** `planningUsage=0`. It does not invent or rerun a Preparation. Original planning usage belongs only to historical lineage. Rebound Seed source preserves the original genuine scope authorization; the additional spend authorization is the new recovery receipt, not a fabricated new natural-language message or second proposal acceptance.

Only the recovery endpoint interprets `inputSource=verified_checkpoint`. Existing execution/binding `input` and base version remain the original authorized base context; they are not falsely labelled as a published checkpoint Version. The actual starting bytes are always the independently verified private checkpoint. Normal delivery endpoints cannot substitute that source. New attempts/report/export bind the new Run/execution and new hashes; old attempts/report are never rewritten or presented as revalidated.

Hash DAG (each object excludes only its own top-level `hash`): source inventory → checkpoint; old request/report + checkpoint → stop receipt; rebound Seed → Spec → Plan → binding → new delivery request; all immutable refs + authorization → recovery wrapper. Semantic hash is over `recoverySemanticBody`, not a self-reference. Schema equality rejects wrong refs/scopes, but consumers must independently compute actual object hashes, the semantic hash, origin request hash, source manifest/snapshot/config hashes and copied bytes. Fixtures with placeholder digests are shape examples, never proof.

## Quote, concurrency and refusal

A quote (persisted in a bounded read cache or deterministically derived from the frozen snapshot/time window) lasts at most 60 seconds and binds checkpoint/source hash, frozen semantic hash, predecessor, exact current project revision/head, and latest Run. Stable polling may return the same quote; expiration or actual source/target change produces a new quote revision. POST with a stale quote returns 409 `STALE_OFFER` without reserving/creating anything. Web rereads, explains the change and requires a fresh explicit click; it never silently changes the source or mints a different authorization key.

After internal source/stop preflight, API's one transaction validates active identity, owner, head/revision/goal, no busy writer/nonterminal work, latest failed predecessor, final rejected original publication, token diagnosis, semantic plan reuse, quote and effective quota. It atomically persists predecessor-level uniqueness plus successor lineage, credit reservation and immutable outbox. Different keys/sessions racing the same predecessor return the original admitted successor; a conflicting body/target is 409. Same key must never admit two Runs. A prior accepted but response-lost operation is reconciled by GET/same-key retry, not a new key. Root/predecessor and successor project scope are checked against the route and actor, not trusted from the client. Report publication/cancellation/base fences remain unchanged; a late original completion can never replace the failed report or publish after successor admission.
