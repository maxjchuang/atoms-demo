# 修复耗尽后的只读复盘：最小协议基线

状态复用 waiting_input + Attention.kind=question。Attention 新增可选 resolution: "replan"，仅宿主为不能继续原冻结计划的复盘/预算等待设置；原 attention wire 保持兼容。此标记要求从现有带回答重新规划入口处理，普通 answers 接口不得恢复旧执行或增加修复额度。用户可补充信息或采用复盘建议，先停止旧执行、发送规划消息、审阅完整方案，明确接受后创建新的有限任务。

Agent：首次验证+最多2次原计划修复仍失败，先在原已知剩余模型/时间/token预算内最多一次只读复盘，模型区分测试/实现/环境/信息不足并依据证据给出理由和建议；不得写源码、测试、改通过状态或追加授权。无预算/未知用量/复盘无效时直接形成有具体上下文的待澄清问题；不因修复轮数耗尽直接fail。原硬取消、信任/来源完整性失败不改为可忽略结果。复盘必须持久化幂等；重启/轮询/回答不得隐式再调用模型。

Backend：复用现有attention事件和等待锁，保留源码/报告/已消费额度，释放计算槽但保持原项目写入所有权；resolution=replan普通answer返回409，不自动增加额度或恢复旧计划。已有RunReplan显式停止后才发送绑定原问题/用户回答的只读规划。

Web：展示复盘理由/具体问题，resolution=replan仅提供带回答重新规划，隐藏普通继续原任务的提交路径。保留明确发送规划与接受完整方案两步，不新增自动构建。

模型验收最多2次真实只读fixture调用，总输入<=16K、输出<=2K，不重放用户任务/不消费构建额度。开发硬截止以本轮起始后20分钟为准，未完成就停止报告。

## 本轮验证结果

- 协议旧测试123项和新增2项均通过；全包类型检查通过。API组合HTTP21/21、Web组合单元11/11；Web独立Mock复盘到重新规划浏览器1/1。Agent组合16/16覆盖耗尽、未知用量、预算不足、软超时、无进展、source/plan篡改、普通问题兼容；实际host clean耗尽等待1/1；最后视图/确认/空问题补漏4/4通过。没有因资源压力并发跑全量浏览器。
- 对真实俄罗斯方块失败记录只读投影为3676字节，保留失败case及明确OMITTED，原source/spec/plan未变；54KB源码模拟仍能发起有界复盘，不再因完整源码大而直接跳过。
- 真实只读模型严格2次，无完整生成/用户任务/构建额度：test类400输入243输出；implementation类555输入190输出，分类符合证据。第二次明确诊断无追问(question空串)被旧parser拒绝，现已修复并用捕获结构离线回放验证；没有第3次真实调用。明确结论使用宿主确认问题，技术追问保留审计但不交给用户；unclear仍需具体产品问题。
- 本轮不复活历史失败任务，不自动修改冻结测试，不自动追加第三次修复或额度。原任务等待时需带回答重新规划、停止核对、显式发送和完整方案确认。
